# Topic fork of Notebook Navigator

This repository is a modified version of [Notebook Navigator](https://github.com/johansan/notebook-navigator) by Johan
Sanneblad, licensed under the GNU GPL v3 (see `LICENSE`). The fork adds topic graph navigation: notes tagged as topics
form a hierarchy in a Topics section of the navigation pane, with topic shortcuts, colors, icons, sorting, and list
appearance settings.

This file records where the fork deliberately differs from upstream and how upstream is merged in.

## Decisions

### Translations fall back to English (2026-10-09)

Since upstream 3.4.1, only English is bundled in `main.js`. Other languages are downloaded at startup from
`https://github.com/johansan/notebook-navigator/releases/download/<version>/languages.json` and accepted only when the
pack's `id` matches `LANGUAGE_DATA_ID` in `src/i18n/localeMetadata.ts`. That id hashes every locale file, and the fork's
locale files contain the topic strings, so upstream's pack never matches. Users with a non-English Obsidian language get
the English UI.

This is accepted to keep fork maintenance low. Alternatives, if this changes:

- Point the URL in `src/i18n/LanguageService.ts` at this repository and publish `languages.json` (generated by
  `npm run build:languages`) with each fork release, tagged with the exact manifest version.
- Bundle all locales into `main.js` again. This conflicts with upstream's i18n code on future merges.

The fork's topic strings use English text in every locale.

### MarkdownPoint banner hidden (2026-10-09)

Upstream 3.4.4 shows a banner for the author's MarkdownPoint app on the settings start page, plus an Advanced toggle
that moves it. The fork hides both with `SHOW_MARKDOWNPOINT_BANNER` in `src/constants/fork.ts`. The upstream banner code
and strings stay in place so upstream edits to them merge without conflicts.

### Versioning

The fork uses upstream's version numbers. Merge branches are named `merge-upstream-<version>`. When a merge includes
unreleased upstream work, the version is bumped to the upcoming upstream version in the same format as upstream's
`Bump version to x.y.z` commits (`manifest.json`, `package.json`, `package-lock.json`, `versions.json`), so upstream's
own bump merges cleanly later.

## Merging upstream

- Upstream rewrote its history after v3.3.6. The fork's original 3.3.6 base (`748f02c9`) and upstream's rewritten 3.3.6
  merge (`8104908c`) have identical trees. The v3.4.4 merge records upstream's real commits as parents, so later merges
  find a normal merge base.
- Upstream checks that every locale has the same keys, so new topic strings go into all locale files.
- After changing locale files, run `npm run build:languages` and commit the regenerated `src/i18n/localeMetadata.ts`. CI
  fails when it is out of date.
- New upstream code that branches on folder, tag, and property selections usually needs a topic case. Topic overrides,
  appearances, pins, and shortcuts are keyed by topic name, while `selectedTopicPath` is the slash-separated path the
  topic was reached through (`getTopicNameFromPath` converts it).
